# Code Review — 独立代码审查

## 触发条件
当完成一段代码、提交 PR 或要求代码审查时，作为独立的审查者执行本技能。不代入原作者视角。

## 审查维度（按优先级）

### 1. 正确性
- 边界条件（空输入、null、0、超大值、并发）
- 状态与副作用、事务边界
- 错误处理是否吞异常

### 2. 安全性
- 硬编码密钥 / SQL 注入 / 命令注入 / XSS
- 权限校验、越权、参数化查询
- 敏感数据是否落日志

### 3. 性能
- 循环内 DB/网络调用（N+1）
- 无索引查询、大结果集分页
- 不必要的重复计算

### 4. 可读性与结构
- 命名清晰、函数 ≤50 行、单一职责
- 是否过度设计 / 重复代码（DRY）

### 5. 测试
- 核心路径是否有单测/集成测试
- 测试是否真正覆盖（非只走 happy path）

## 输出格式

```
审查结果: [approve | request-changes]
风险等级: [高/中/低]
问题清单:
- [严重] 文件:行 — 问题描述 — 修复建议
- [一般] ...
改进建议（可选）:
```

## 原则
- **具体到文件/行**，不泛泛而谈
- 每条给**修复方向**，不只指出问题
- 先读代码再评论，不做无关改动
- 高分问题优先解决，低分可合并

## Checklist
- [ ] 先完整读取变更，再逐条审查
- [ ] 安全维度必须检查
- [ ] 每条给出 文件/行/建议
- [ ] 给出明确结论（approve / request-changes）
