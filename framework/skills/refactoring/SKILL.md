# Refactoring — 安全重构

## 触发条件
- 需要改进代码结构/可读性/可维护性，但**不改变功能**时。

## 原则
- **行为不变**：重构不改变外部行为与接口契约
- **测试兜底**：先有守护测试（snapshot / 行为测试），再动代码
- **小步提交**：一次重构一个关注点，每个 commit 可回退

## 流程

### 1. 建立行为守护
- 对目标写 snapshot / characterization 测试锁定当前行为
- 全部通过后再重构

### 2. 定位重构点
- 重复代码、过长函数、坏味道（命名、职责、耦合）
- 明确"改什么 / 不改什么"（范围）

### 3. 执行重构
- 小步、每步一个行为：重命名 → 提取 → 简化 → 拆解
- 每步后跑守护测试，确保仍绿

### 4. 验证
- 守护测试全部通过
- 相关测试无回归；覆盖率不下降

## 输出
```
重构范围: ...
守护测试: ...
改动清单: 每步行为 + 验证
回归结果: 全部通过
```

## Checklist
- [ ] 先建行为守护测试
- [ ] 范围明确（不改行为）
- [ ] 小步提交、每步可回退
- [ ] 守护测试全绿、无回归
