# 系统架构设计

## 触发条件
- 新系统/新模块设计、技术选型、重构架构时使用。

## 设计流程

### 1. 明确约束与目标
- 功能需求 + 非功能（性能、可用性、安全、成本、团队规模）
- 明确边界（做什么 / 不做什么）

### 2. 模块与分层
- 按职责分层（如 API→Service→Repository），单一职责
- 模块间通过接口/契约交互，降低耦合
- 依赖方向单向，避免循环依赖

### 3. 数据流与状态
- 明确数据从哪来、怎么流转、如何存储
- 数据模型与迁移策略（见 api-design / database）

### 4. 技术选型
- 基于约束选型：成熟度、生态、团队熟悉度、成本
- 列出备选对比（权衡表）

### 5. ADR 记录
- 每个关键决策用 ADR 记录（背景/决策/权衡/影响）
- 追加到 `context/architecture.md`

## 输出
```
架构设计:
- 分层/模块图
- 数据流
- 技术选型 + 权衡
- ADR 引用
- 演进路线
```

## 原则
- **简单优先（KISS）**，不为不存在的问题过度设计
- **可测试**：模块边界清晰，易于 mock
- **可演进**：接口稳定、可扩展

## Checklist
- [ ] 分层清晰、无循环依赖
- [ ] 非功能需求已考虑
- [ ] 选型有对比权衡
- [ ] ADR 已记录
