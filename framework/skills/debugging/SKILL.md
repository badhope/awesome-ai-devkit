# Debugging — 系统化问题调试

## 触发条件
- 功能报错、测试失败、性能异常、行为不符预期时

## 调试流程

### 1. 复现问题
- 获取最小复现步骤（最小输入/最小环境）
- 记录报错信息、日志、环境（版本/OS）

### 2. 定位根因（二分排除）
- 读取报错堆栈 → 定位到具体文件/行
- 检查输入数据、边界条件
- 用日志/断点/二分法缩小范围
- **问"为什么"到根因**，不要停在表面症状

### 3. 修复
- 最小改动：只改根因，不夹带无关重构
- 保持接口/行为一致（除非必要）

### 4. 验证
- 写一个**回归测试**复现原 bug，修复后通过
- 跑相关测试确认无回归
- 检查边界场景

## 常见误区
- 只改表面（报错处）而非根因
- 不写回归测试就宣布修复
- 忽略并发/数据/状态导致偶发

## 输出格式
```
问题: <现象 + 复现>
根因: <定位到的真正原因，含 文件:行>
修复: <改动说明>
验证: <回归测试 / 相关测试结果>
```

## Checklist
- [ ] 已最小复现
- [ ] 根因明确（非表面）
- [ ] 有回归测试
- [ ] 相关测试全部通过
