# 需求分析

## 触发条件
- 收到模糊/复杂需求，需澄清为可交付、可验收的规格时。

## 流程

### 1. 澄清需求
- 识别**目标**（解决什么问题）而非只听表面请求
- 补齐缺失：谁用、什么场景、何时、成功标准
- 识别约束（性能、合规、兼容、成本）

### 2. 范围控制
- 明确 "In scope / Out of scope"
- 识别依赖与前置（数据、其他模块、第三方）

### 3. 拆解
- 将大需求拆成可独立交付、可验收的功能单元
- 标优先级（MUST / SHOULD / NICE）

### 4. 验收标准（BDD）
```
Given 前置条件
When  执行动作
Then  期望结果（可测）
```

## 输出
```
需求规格:
- 目标
- 范围（in/out）
- 用户场景
- 功能清单 + 优先级
- 验收标准（G/W/T）
- 约束与风险
```

## 原则
- **目标导向**，不止复述需求
- **可验收**，每条都有判断标准
- **主动澄清**，不臆造

## Checklist
- [ ] 目标/范围明确
- [ ] 歧义已澄清
- [ ] 验收标准可测试
- [ ] 有优先级与约束
