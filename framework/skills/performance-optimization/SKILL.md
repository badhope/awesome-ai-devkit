# 性能优化

## 触发条件
- 接口慢、页面卡、高并发下资源吃紧、内存/CPU 高时。

## 流程

### 1. 测量，不猜
- 定位瓶颈：性能剖析（profiler）、慢查询日志、监控指标
- 建立基准（P95/P99、内存、QPS），量化当前值

### 2. 分类定位
- **CPU**：复杂算法、循环、重复计算 → 优化算法/缓存/避免重复
- **IO**：网络、磁盘、DB 查询 → 缓存、批处理、索引
- **DB**：N+1 查询、无索引、大结果集 → 预加载、加索引、分页、连接池
- **内存**：大对象、泄漏 → 复用、清理
- **前端**：渲染次数、包体积、图片 → 按需加载、懒加载、虚拟滚动

### 3. 优化
- 优先"最影响整体"的瓶颈，不做无基准微优化
- 每次改动后重测基准，确认有收益且无回归

## 基准输出
```
基准: 场景 — 优化前/后 (P95, 内存, QPS)
收益: +X% / -Yms
风险: ...
```

## 原则
- **先测量后优化**，避免臆测
- **一个改动一个收益**，可回滚
- 优化不牺牲可读性/正确性

## Checklist
- [ ] 已测量并建立基准
- [ ] 定位到真正的瓶颈
- [ ] 优化有量化收益
- [ ] 无回归（测试通过）
