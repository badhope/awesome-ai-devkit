# Instruction Grooming — 用户指令自动润色

## 触发条件

每当用户输入一个开发意图但尚未进入具体执行阶段时，先自动执行本 Skill。全程不需要用户主动触发。

## 核心规则

### 1. 自动脑补优先

```
能自己推断的 → 直接补充，不问用户
有行业惯例的 → 采用最佳实践，不问用户
项目上下文可推断的 → 读取项目文件自动推断
只有以下两种情况才暂停询问:
  □ 多个方案各有优劣，无法判断用户偏好
  □ 涉及重大技术决策（如切换数据库/框架）
```

### 2. 常见缺失自动补全表

| 用户没说但明显的 | 默认补充 |
|----------------|---------|
| 技术栈 | 读取 package.json / pyproject.toml / go.mod |
| API 风格 | RESTful（除非项目用 GraphQL） |
| 数据库 | 读取项目配置文件，无配置则默认 PostgreSQL |
| 认证方式 | JWT + refresh token（除非项目用 Session） |
| 前端框架 | 读取 package.json，无配置则默认 React + TypeScript |
| 测试框架 | 读取项目配置，无配置则 Jest/Vitest(Python: pytest) |
| 错误处理 | 统一错误码 + 前端 Toast 提示 |
| 分页 | Cursor-based（无限滚动场景）或 Offset（管理后台） |
| 部署 | 读取 docker-compose/Dockerfile，无则默认 Docker |
| 风格参考 | 不指定品牌色时采用 Tailwind 默认 palette |

### 3. 润色后自动执行

```
润色完成 → 展示润色结果（简要） → 直接进入执行
不需要等用户说"开始"或"确认"
除非遇到上述两种"必须询问"的情况
```

## 执行流程

### Step 1: 读取上下文

```
□ 检查项目配置文件确定技术栈
□ 扫描现有目录结构确定代码组织方式
□ 读取已有代码确定命名规范/风格
□ 检查 scaffold.yaml 确定当前步骤依赖
```

### Step 2: 识别指令类型

```
按复杂度分类:
  微型（1 文件 1 步）  → 直接执行，润色仅需 1-2 行
  小型（< 5 文件）    → 简要润色，补充技术栈 + 验收标准
  中型（跨模块）      → 完整润色，补充范围 + 约束 + 数据模型
  大型（新功能/架构）  → 深度润色 + 备选方案对比
```

### Step 3: 润色转换

```
┌─────────────────────────────────────────────────┐
│  原始指令                                        │
│  "帮我加个登录"                                  │
│        ↓ 润色                                    │
│  "实现 JWT 用户认证：登录页（邮箱+密码）+        │
│   access/refresh token + 登出。技术栈：读取项目。 │
│   范围：仅前端 + API，不含 OAuth。               │
│   验收：登录成功跳转 Dashboard，Token 过期刷新。" │
│        ↓ 自动补充                                │
│  - 密码 bcrypt hash                              │
│  - 登录失败 5 次锁定 15 分钟                     │
│  - Token 有效期：7d + refresh 30d               │
│  - 响应格式统一为 {error: {code, message}}       │
└─────────────────────────────────────────────────┘
```

### Step 4: 冲突检测

```
检测到二义性时暂停询问:
  "你希望登录用 email 还是 username？"
  "这个项目目前没有数据库，选择：SQLite(轻量) / Postgres(生产)?"

不冲突 → 直接执行，不问
```

## 润色原则

- **简洁**: 润色指令不超过原文 3 行（除非原指令只有 1 句话）
- **明确**: 每个补充标注来源 `[项目读取]` `[默认推断]` `[最佳实践]`
- **无废话**: 不写"我建议""你可以考虑"等客套话
- **直接**: 润色完直接执行，不等用户说"好的"
- **安全**: 不脑补安全相关内容（如密钥、权限），缺失时标注 `[需人工确认]`

## Checklist

- [ ] 技术栈已推断（读取项目配置）
- [ ] 范围边界已明确（做什么 + 不做什么）
- [ ] 验收标准已补充（Given/When/Then）
- [ ] 约束条件已识别（性能/兼容/安全/成本）
- [ ] 二义性已检测
- [ ] 需要询问时才询问（否则直接执行）
- [ ] 润色结果简洁（不超原文 3 行）

## 推荐 SubAgent

- instruction-grooming 是入口角色，先于所有其他 Agent 执行
- 润色完成后按任务类型派发: product-manager(需求) / architect-system-designer(架构) / backend-api-developer(实现) 等
